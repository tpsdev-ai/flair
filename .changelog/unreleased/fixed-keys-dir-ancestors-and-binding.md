- **On POSIX, when flair writes a new key it refuses a keys directory with an ancestor another user can change.** Provisioning binds the key to the checked directory. The same check runs before an existing key is reused and before `flair agent rotate-key` takes its lock or writes its backup, so a key under such a directory is refused too. The check covers every ancestor of the keys directory's resolved path and runs before the keys directory is created or its mode is changed. An ancestor inside flair's home (`~/.flair`, when it is a directory and not a symlink) that you own and that is group- or world-writable is tightened instead, with one notice naming the directory and its old and new modes; any other failing ancestor is refused by name with its owner and mode. If the keys directory is no longer the one that was checked when the key is linked, the command stops; a key written into a replacement directory is removed, and a key that landed in the checked directory before it moved is reported, not removed. To use a refused keys directory, move it under ancestors owned by root or yourself that are not group- or world-writable (sticky directories such as /tmp are accepted), or fix that ancestor's owner or mode. ([#3138](https://github.com/tpsdev-ai/flair/issues/3138))
