- **A new agent key's directory entry is synced before registration on POSIX, including when a retry reuses the key.** On POSIX a reused or raced key's directory is synced before it is returned, and a new keys directory's parent is synced when it is created, including a directory another process created between the check and the mkdir; a retry that finds the directory in place repeats the sync of its own entry. A failed sync before registration refuses; after `flair agent rotate-key` installs a key, a failed sync warns and the new key stays in place. A direct `createAgentKeyFile` call leaves the published key in place; `flair mcp grant` tries to remove a key it just published when a later step fails, and names any key file it could not remove. On POSIX a keys path that is a symlink, a non-directory or another owner's directory is refused. Windows does not sync or check these paths.
