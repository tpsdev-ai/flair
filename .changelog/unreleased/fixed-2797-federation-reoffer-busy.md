- **An eligible Memory row the hub refused because the row was locked is offered again on a later sync while its pending obligation exists.**
  The sender keeps one pending row per (hub, Memory, record) in `FederationRetry` when the hub's refusal is retryable, and offers it again independent of its sync cursor, so the refusal no longer waits for the row itself to change. A non-retryable refusal leaves a terminal row that the retry path does not select again (a later row update can still select it through the ordinary cursor). A deleted or private source is recorded as a terminal outcome instead of being offered. The federation sync response also says whether its SyncLog row was written (#2797, #2792).
