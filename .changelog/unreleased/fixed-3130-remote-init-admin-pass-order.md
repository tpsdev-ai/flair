- **Remote `flair init` saves Flair's administrator password before the cluster change that applies it.** A credential file is written only when this run sets `admin`'s password: created when none exists, otherwise the new value is staged in a mode-0600 sibling and renamed over the file after the cluster accepts it. A run that reuses an existing super_user writes no file. A failed save exits non-zero, names the file and leaves the cluster unchanged. When an existing file's staged sibling cannot be published after the cluster accepts the password, the sibling is kept and init names it with the step to take.
