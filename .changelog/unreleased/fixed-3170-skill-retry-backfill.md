- **An identical skill POST retry is no longer refused when the previous write's embedding backfill commits before its target read.**
  The race the retry accepts is a backfill commit after its request transaction opens and before its target read. For a target present in the request snapshot, the POST then reads the target as committed and plans in an owned transaction, so the plan's read sees the backfill the request snapshot missed. A change to the target's content, with ownership unchanged, committed after the target read and before the plan still answers 409 `skill_target_changed`.
