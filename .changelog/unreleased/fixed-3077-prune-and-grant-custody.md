- **`flair keys prune --apply` archives keys owner-only, and `flair mcp grant` checks the Agent id before writing and keeps custody of its key files.** `mcp grant` refuses before any key or Agent record write when the existing-Agent lookup fails: a non-2xx or transport failure, an unreadable body or a non-list response is reported with the status where there is one and the Agent id. Before the insert request is sent, cleanup runs without a server acknowledgement. A delete for the Agent is sent only when the insert's result body names the Agent id in `inserted_hashes`, does not name it in `skipped_hashes` and carries no `error`, and a later step then fails: a delete whose result body names the id in `deleted_hashes` with no error or skipped id removes the keys when that cleanup succeeds and names any key it keeps, and any other delete result says the Agent may exist and keeps the keys. An insert the result body does not confirm — an error response, timeout, transport failure, unreadable body, a skipped id or an absent id — sends no delete and keeps the keys; the error says the outcome is unknown and how to check and remove the Agent row. On POSIX the archive directory must be a directory the current user owns with no group or other bits (a missing one is created that way, an existing wider one is tightened); where `process.getuid` is unavailable the archive move is refused and nothing is moved. A successfully moved private key is left at `0600`, and a key whose `chmod` fails or that is still wider after it stops the command with the `chmod 600` remedy.
