- **`GET /AdminMemoryCandidates/{agentId}` refuses an agent id that Harper's path parsing changed, instead of listing another agent's candidates (#2845).**
  When the text after a path id's first dot is `json`, `csv`, `cbor` or `msgpack`, Harper's path parsing drops the dot and that text, so a request for `agent.json` (the dot raw or encoded) reaches the route as `agent`. An admin's request of that kind is now answered with `400 agent_id_rewritten`, naming the requested and the received id. `GET /WorkspaceLatest/{agentId}`, `GET` and `POST /AgentReadPosition/{agentId}`, `GET` and `POST /OrgEventCatchup/{participantId}`, `GET /MessageInbox/{to}`, `GET /MessageDeadLetter/{from}`, `GET /AgentCard/{agentId}` and `GET /MCPClientMetadata/{agentId}` answer such a request the same way once it passes the route's existing authentication check; the two `POST` forms advance no read position for it. A request whose path id reaches the route unchanged is answered as before.
