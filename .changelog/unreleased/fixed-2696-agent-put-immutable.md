- **Agent PUT is an administrator operation that updates an existing agent, keeping its stored `createdAt` and `publicKey`; an agent updates its own record with PATCH.** A PUT from any other verified agent is refused 403 (`agent_put_admin_only` when the record exists). An administrator's PUT to a missing id is refused 404 `agent_put_requires_existing`; `POST /AgentSeed` is a creation path, the one the refusal names, and `POST /Agent/` also creates a row (administrators only). An administrator's PUT stores the fields its body names, so a field it omits (`status` and `role` included) is not kept. The replacement is built from a re-read of the row in the PUT's own write transaction: a deletion or a key rotation committed after the PUT's first read and before that re-read is seen (a deleted agent is refused with the same 404, a rotated key is kept), and one whose transaction takes its time after the re-read is applied after the PUT's write. For a non-admin PATCH, an admin-status change is decided from the `role` of the row the guard reads and the role that row would have once the body is merged and reconciled; the `admin` mirror is not read as authority, and an administrator's change whose transaction takes its time after that read is applied after the PATCH. A key is rotated by `flair agent rotate-key`, an `update` through Harper's operations API.
