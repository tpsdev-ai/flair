- **Agent PUT updates an existing agent, keeping its stored `createdAt` and `publicKey`; an otherwise admissible PUT to a missing id is refused 404 `agent_put_requires_existing`.** The authorization refusals come first: a signed non-admin PUT that includes `status`, for example, is refused 403. The replacement is built from a re-read of the row in the PUT's own write transaction: a deletion or a key rotation committed after the PUT's first read and before that re-read is seen (a deleted agent is refused with the same 404, a rotated key is kept), and one whose transaction takes its time after the re-read is applied after the PUT's write. For a non-admin caller, PUT and PATCH decide an admin-status change from the stored `role` and the role the reconciled record will have; the `admin` mirror is not read as authority. `POST /AgentSeed` is a creation path, the one the refusal names; `POST /Agent/` also creates a row (administrators only). A key is rotated by `flair agent rotate-key`, an `update` through Harper's operations API.
