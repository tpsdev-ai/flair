- **Durability docs now state what each tier does and does not guarantee (flair#2217).** `permanent` had been described as "retained until explicitly deleted", which over-promised: the code gives it no special flush, fsync, backup or replica acknowledgement, and an explicit delete or a store failure ends a row at any tier. Every place a writer or agent picks a durability — the MCP tool descriptions, the CLI `--durability` help, the SDK doc comments, the shipped skills, README and the docs — now carries the same per-tier statement, and a contract test fails if any of them drops it or re-introduces such a promise.
