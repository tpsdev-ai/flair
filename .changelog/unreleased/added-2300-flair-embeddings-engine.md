- **Opt-in in-process embeddings via `FLAIR_EMBEDDINGS_ENGINE=flair`.** Unset, Flair still embeds with harper-fabric-embeddings and the same stamp. With the variable set to `flair`, Flair loads the optional platform prebuilt for this host (`@node-llama-cpp/linux-x64`, `@node-llama-cpp/linux-arm64`, or `@node-llama-cpp/mac-arm64-metal`, exact `3.18.1`) and a SHA-256-pinned nomic model file (flair#2300). A missing or unsupported prebuilt skips embedding registration and leaves keyword search. A rejected download, and a failure to create or stat the models directory, is reported as that failure, not as a prebuilt that did not load. The models directory is created mode 0700 when it is absent, and refused when it is group-writable, other-writable, or owned by another user. Successfully embedded new writes use a `flair:<digest>` stamp. A write that stays on keyword search receives no embedding stamp. The existing store is not re-embedded by the automatic migration.

  > **Heads-up:** `FLAIR_EMBEDDINGS_ENGINE=flair` changes the stamp on successfully embedded new writes. The automatic migration does not re-embed rows already in the store. Leave the variable unset to keep today's engine and stamp.
