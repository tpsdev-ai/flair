- **An auto-promotion whose candidate update fails is reported as incomplete, and the next sweep marks the candidate promoted without writing a second memory.** `POST /AutoPromoteCandidates` used to list such a promotion under `promoted` while its candidate stayed pending. It now lists it under a new `incomplete` field as `{ memoryId, candidateId, error }`, and the entry does not count toward `promoted`, `count` or the per-call `limit`. The next sweep adopts the memory recorded on the candidate when that memory still carries the sweep's own approval bound to its current content (`promotionStatus` `approved`, `promotedBy` `machine:adk-auto-promote`, matching `promotionContentHash`). The sweep then marks the candidate promoted and reports that memory id under `promoted`; before this change it wrote a second promoted memory. The same applies when an earlier stamp was reported unconfirmed but did land. The REM runner records the incomplete count on its log row, and `flair rem nightly run-once` prints it on the `Auto-promoted:` line. A newly written auto-promoted memory now gets a random id, as `PromoteMemoryCandidate` already does (#2714).
