- **`flair init` seeds an org-wide `using-flair` skill so a new agent's bootstrap can list it with no per-agent setup (flair#2141).**

  The seed writes one skill-tagged Memory row (`skill:using-flair`, persistent, shared, owned by the operator that ran it) and a fixed-id org-scope assignment that an active agent principal receives unless it opts out or the entry exceeds the bootstrap budget. Only the operator (an authenticated Basic administrator) can create, replace, patch, supersede or delete that Memory row, and a federation peer's row is not merged onto it. A re-run reads both rows by their fixed ids, so it writes only what is missing or outdated. A stored text that matches a listed shipped version is replaced; any other text is kept and reported. Before it writes, `flair init` refuses with a remedy, writes nothing and exits non-zero when a read fails, when an Agent record has the operator's id, when the existing row is not the operator's, its content is not text, or it is not a live org skill (no `skill` tag, not shared, archived, closed or expired), or when the existing assignment differs from the seed's. After each write it reads the row back and applies the same checks before it reports success.

  The text reconciles the flair best-practices guidance and the cursor-flair skills (remember, bootstrap, coordinate, soul): when to write and at what durability, provenance, recall habits, what not to store, identity, and — until a directory tool lands — the Agent and Presence records for who is in the office.
