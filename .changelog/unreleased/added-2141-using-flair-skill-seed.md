- **`flair init` seeds an org-wide `using-flair` skill so a new agent's bootstrap can list it with no per-agent setup (flair#2141).**

  The seed writes one skill-tagged Memory row (`skill:using-flair`, persistent, shared, owned by the operator that ran it) and a fixed-id org-scope assignment that an active agent principal receives unless it opts out or the entry exceeds the bootstrap budget. A re-run reads both rows by their fixed ids, so it writes only what is missing or outdated. A stored text whose hash is in the repo's shipped-hash list is an unedited shipped version and is replaced; any other text is locally modified or unrecognized, and is kept and reported. A malformed or unreadable row, or an assignment naming another skill row, refuses the seed with a remedy; every write is checked and read back, and `flair init` fails rather than report success.

  The text reconciles the flair best-practices guidance and the cursor-flair skills (remember, bootstrap, coordinate, soul): when to write and at what durability, provenance, recall habits, what not to store, identity, and — until a directory tool lands — the Agent and Presence records for who is in the office.
