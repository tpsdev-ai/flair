- **`flair mcp enable --cimd-allowed-hosts` now writes the allowed-hosts list when the target runs from the edited `config.yaml`, and refuses otherwise.** In 0.57.0 the flag's value only appeared in the command's output, and the list the instance used did not change.

  The command writes `mcp.clientIdMetadataDocuments.allowedHosts` into the `config.yaml` it edits for `mcp.enabled` on the machine it runs on (`./config.yaml`, else `~/.flair/config.yaml`). It does so only when the target's operations API reports this machine's hostname and a Harper process on this machine that was started with that file's directory as its application directory. It reads the file back before restarting the instance, and prints the list it read. If the write or the read-back fails, the command stops before the restart. It refuses the flag before changing anything for a `*.harperfabric.com` instance, for a target it cannot match to that file, for an entry that is not a lowercase bare hostname (such as a URL, a port, a wildcard or an empty entry), and when that `config.yaml` is missing or has no `@harperfast/oauth` `mcp` block. With `--dry-run` it checks the hostnames and the file, not the target, and writes nothing. Without the flag the list is not changed.

  A successful `flair mcp enable` run (without `--dry-run` or `--json`) now ends by saying the OAuth metadata check passed, not "claude.ai can now connect."; that check does not probe `/mcp` or read the list.
