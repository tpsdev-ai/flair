- **`flair mcp enable --cimd-allowed-hosts` now writes the allowed-hosts list when the target runs from the edited `config.yaml`, and refuses otherwise.** In 0.57.0 the flag's value only appeared in the command's output, and the list the instance used did not change.

  The command writes `mcp.clientIdMetadataDocuments.allowedHosts` into the `config.yaml` it edits for `mcp.enabled` on the machine it runs on (`./config.yaml`, else `~/.flair/config.yaml`). It does so only when the target's operations API reports this machine's hostname and a Harper process on this machine that was started with that file's directory as its application directory. It reads the file back before restarting the instance, and prints the list it read. If the write or the read-back fails, the command stops before the restart. It refuses the flag before changing anything for a `*.harperfabric.com` instance, for a target it cannot match to that file, for an entry that is not a lowercase bare hostname (such as a URL, a port, a wildcard or an empty entry), and when that `config.yaml` is missing or has no `@harperfast/oauth` `mcp` block. With `--dry-run` it checks the hostnames and the file, not the target. Without the flag the command does not inspect or change the list.

  In a successful `flair mcp enable` run (without `--dry-run` or `--json`), the closing summary after the step list now opens with "The OAuth metadata check passed. The /mcp route itself was not probed." instead of "claude.ai can now connect."; the claude.ai note, when it applies, and the connector paste block follow it. That check reads only the authorization-server metadata.

  `flair mcp enable --dry-run` no longer creates the signing key. It reports the path where a run without `--dry-run` would reuse or generate one, and writes no file.
