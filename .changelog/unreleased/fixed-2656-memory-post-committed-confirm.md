- **A Memory `POST` that owns its transaction checks its committed row.** An in-process POST with no caller transaction commits on its own, then confirms the incarnation token and its staged `agentId`, `content`, `visibility` and `durability` (a skill POST also `summary`, `trigger`, `metadata` and `tags`). A same-id replacement that changes the row's identity and is observed by that check answers 409 (`stored_row_changed` for an ordinary POST, `skill_target_changed` for a skill POST); an unreadable row answers 503 `write_outcome_unknown`. A POST inside an open caller or request transaction stays joined and checks the committed identity before the commit; its post-commit verification is deferred (#2656 slice B).
