- **Remote `flair init` refuses a cluster user list that does not confirm the authenticated cluster administrator exactly once.** Provisioning also refuses a list with more than one `admin` record before staging a credential or writing. It sends `add_user` when the list has no `admin` record and `alter_user` when it has one; a listed super_user cluster administrator takes the reuse branch without an `admin` write. It also refuses case and whitespace variants of the reserved `flair-agent` name, and requires an array of objects with non-empty string usernames and boolean `super_user` permissions. The `--admin-user` help now describes this reuse.
