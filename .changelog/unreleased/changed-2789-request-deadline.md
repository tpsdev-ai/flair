- **A write that reaches its whole-request deadline reports an unknown outcome, never a failure, and exits 3.** `FLAIR_REQUEST_TIMEOUT_MS` sets the whole-request deadline (the request and the response body read): an integer from 1 to 3600000 ms, default 300000. The CLI's `POST /MemoryMaintenance` and `POST /ReflectMemories` calls use a 900 s deadline instead. A GET or HEAD that expires fails; a write that expires raises `ApiRequestOutcomeUnknown` and is not retried. `flair rem light`, `flair rem rapid`, `flair rem restorative`, `flair rem promote`, `flair rem reject` and `flair rem nightly run-once` print the unknown outcome and exit 3; `flair rem restore` reports `unresolved` and exits 3, and does not write a table and record id again in that run after any unknown write to it; `flair federation prune --apply` prints one line per peer whose DELETE is unknown, keeps it out of the error count, and exits 3. A command that lets the error propagate reports it at the top level as `Unknown outcome:` and exits 3. Writes the CLI sends with a bare `fetch` (the ops API and `authFetch`) are outside this deadline mechanism. A nightly log append that fails after an unknown write still exits 3 and prints the log failure. A completed post-restore verification reports whether each unknown memory or soul id was present in its read and what an id-only check cannot decide; candidate readback is a follow-up (flair#2789).
